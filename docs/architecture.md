# Brickpress 2 architecture

Brickpress 2 is a native Rust application built on eframe, egui and wgpu. It
replaced the SvelteKit/Tauri editor (1.x), which was removed from the
repository in 2.0.0 (it remains in Git history and in the v1.1.0 release). The
project format, piece catalog and device state are unchanged, so files and saved
data from 1.x open in Brickpress 2.

```
crates/
  brickpress-core/    document model, catalog, geometry, collision, editing, agent ops
  brickpress-render/  wgpu renderer: board, print engine, 3D, offscreen export, SVG
  brickpress-mcp/     MCP server (stdio), headless backend and the live client
  brickpress-app/     the eframe GUI; also the `brickpress` binary, including `brickpress mcp`
```

## Core (`brickpress-core`)

- `document`: the version-1 `.brickpress.json` format, field-for-field with
  1.x. Integral numbers are written without a fraction, as JavaScript does.
  Each pass keeps its piece list in an `Arc`, so an undo snapshot copies only
  the passes an edit touched.
- `catalog`: the read-only `lego-letterpress-kit` catalog, embedded at compile
  time. Malformed entries are dropped with a warning. Every
  rotation × mirror pose is prepared once: its mask, cells and flattened surface.
- `geometry`, `silhouette`, `spatial`: placement origins are the top-left of
  the rotated footprint. Collision is checked in two stages: the pose masks
  find candidates, then the exact surfaces decide. Touching edges do not count
  as overlap.
  `OccupancyIndex` is a dense per-cell index. The editor caches it per
  document generation, so hover checks cost well under a microsecond on a
  10,000-piece board.
- `editor::EditorCore`: every mutation goes through `commit` (clone, apply,
  skip no-ops, push history, mark dirty). Placement strokes and live gestures
  such as slider drags and colour picking are transient and commit once.
- `ops`: serializable operations for agents. Each operation is one undo step.
- `tests/parity.rs`: the starter document is byte-identical to 1.x, and 4,000
  random pose pairs collide exactly as in 1.x. The fixtures were generated by
  the TypeScript implementation.

## Renderer (`brickpress-render`)

- **Shape atlas**: a signed-distance field for each catalog piece (64 texels
  per stud) in one R16F texture. Design mode insets the 0.2 mm printing gap
  from it and anti-aliases analytically. Selection outlines, ghosts and the
  print edge effects come from the same field.
- **Instanced 2D pipeline**: one instance per piece, in paint order, in a
  single draw. Instances are rebuilt only when the document, the mode or a
  drag offset changes (about 0.4 ms for 10,000 pieces). Pan and zoom only
  change a uniform.
- **Print engine v2** (`shaders/pieces.wgsl`): the per-piece jitter, rotation,
  opacity and per-pass registration formulas are the 1.x ones (`print.rs`), so
  the sliders keep their meaning. The surface texture is modelled on real
  brick letterpress prints, and was tuned against photographs with
  `cargo run --release -p brickpress-render --example print_lab -- OUT_DIR [px_per_stud] [presets]`:
  - ink lands as a dense film; where it fails to transfer, the paper shows
    through as sharp-edged voids, not as a paler tint;
  - two void mechanisms: fractal *flakes* in piece space (wear, coverage,
    ink starvation) and fine *speckle* from the paper's tooth in board space,
    which clusters where the film is thin;
  - the amount varies strongly from piece to piece and in broad patches
    within a piece, and the rim of each surface holds ink best;
  - outlines are eroded, slightly ragged and chipped;
  - thresholds are set from the wanted void fraction with unit-variance noise
    (`fbm_unit`, `covered`), so the look is the same at every zoom; below a
    pixel it falls back to the mean coverage;
  - the Clean preset (and any setting with no distress) prints flat.

  Inks overprint with multiply blending, and everything is seeded and
  deterministic. `font/print_sim.py` ports the **1.x** SVG print filters and no
  longer matches this look.
- **Export**: the same pipelines render offscreen in 2048 px tiles, up to
  12,000 px per side and 40 MP. SVG design exports are pure vector with gap
  masks. SVG print exports keep the vector pieces, with their jitter, and mask
  each pass with its rendered coverage texture (embedded PNG).
- **3D**: lyon-tessellated, inset and extruded pieces; instanced studs on a
  baseplate; one shadowing light; 4× MSAA offscreen, then blitted into the UI.
  The orbit camera is ported from 1.x along with its tests. Rays are computed
  in view space for f32 accuracy.

## App (`brickpress-app`)

- `commands.rs` defines every action once: label, icon, shortcut,
  availability (with a reason when disabled) and checked state. The menus,
  toolbars, context menus, tooltips, command palette (Ctrl/⌘ K) and keyboard
  handling all read from it.
- `theme.rs` holds the design tokens from `docs/ui-design.md`. Light and dark
  follow the system, and a unit test checks their WCAG contrast. Inter is used
  for the UI, IBM Plex Mono for numbers and Lucide (subset) for icons.
  `widgets.rs` is the component kit (buttons, icon buttons, segmented controls,
  tabs, sections, sliders, switches, swatches, colour picker, empty states).
- `storage.rs`: project and export writes are atomic and fingerprint-checked.
  If the file changed on disk, the save becomes a conflict ("Save a Copy").
  Device state lives in the same application data folder as 1.x, under the
  same record names (`recovery`, `presets`, `preferences`, `trace-metadata`,
  `tracing/*.bin`), plus `app.json`. Writes run on a background thread.
- Documents open in tabs (`tabs.rs`). `BrickpressApp` holds `tabs:
  Vec<DocumentTab>` and the `active` index; each `DocumentTab` owns its
  `EditorCore` (document, history, selection), `TrackedFile` (path and
  fingerprint), tracing guide, 2D view and 3D camera. Panels, commands and the
  window title read the active tab through `app.core()` / `app.tab()`. The
  window-wide editor state (presets, preferences, clipboard, the piece being
  placed) moves to the newly active tab (`EditorCore::adopt_shared`) and is
  kept on a "shelf" editor when no tab is open; then the canvas shows an empty
  state and non-global commands are disabled with a reason. New, Open and Open
  Preset as New Project (`document_from_preset`) add a tab; an untouched
  starter document makes way, and an already open file is activated instead.
  Close (Ctrl/⌘ W, middle-click, ×) asks Save/Don't Save/Cancel for that tab;
  Quit asks about each unsaved tab in turn.
- A cancelled or failed Open/Save leaves every open document, selection, guide
  and history untouched. Each unsaved tab autosaves (debounced) to its own
  `recovery-<uuid>` record, listed in `app.json` with the tab order, files,
  views and guides, so a crash restores every unsaved tab. The 1.x-compatible
  `recovery` record mirrors the active unsaved tab (or the first unsaved one),
  and state from single-document versions still restores from it.
- `agents.rs`: the live MCP endpoint. It is opt-in and per-user, and requests
  are applied on the UI thread to the active tab, one undo step each.

## Tests

```sh
cargo test --workspace                     # unit, parity, GPU render, UI (kittest) and MCP tests
cargo test --release -p brickpress-render --test perf -- --nocapture
BRICKPRESS_ARTIFACTS=/tmp/shots cargo test -p brickpress-app --test ui   # keep screenshots
```

GPU tests use the platform's software adapter where there is no GPU. UI tests
drive the real app through AccessKit labels, rendered with wgpu.
