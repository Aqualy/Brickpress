# Desktop bridge

Brickpress shares one Svelte editor between browsers and Tauri. Native APIs are
loaded only after client mount. The Rust backend owns filesystem paths; opaque
tokens identify files explicitly chosen in system dialogs. Tokens never enter
`PressDocument` and do not survive restarting the app.

## IPC contract

All argument names and returned properties use camelCase. Failures reject with
`{ code: string, message: string }`; cancellation returns `null` or the explicit
choice below. Commands are available only to the local `main` window.

- `select_file({ kind, save, defaultName? })`: returns
  `{ token, name, path, mime } | null`. `kind` is `project`, `presets`, `trace`,
  `png`, or `svg`. Inputs are limited to 20 MB before reading. `path` is for
  display only; no command accepts arbitrary filesystem paths.
- `read_selected_file({ token })`: returns a raw ArrayBuffer, limited to 20 MB.
  The file's fingerprint is captured when selected and checked when read.
- `write_selected_file`: takes a raw Uint8Array/ArrayBuffer request body and the
  header `x-brickpress-token`. Atomically replaces the selected file. Always
  checks its prior fingerprint; changes/deletions produce code `conflict`.
  Updates the fingerprint after a successful write. Project/preset writes have
  a 20 MB limit; raster/vector output has a 200 MB limit.
- `release_file({ token })`: forgets a file token after failed/cancelled Open or
  after an export. Keep the current project token until replaced or closed.
- `read_state({ key })`: returns persisted UTF-8 text or null.
- `write_state({ key, value })`: atomically writes text; null deletes the record.
- `quarantine_state({ key })`: moves an invalid state record aside for inspection.
  State keys are `recovery`, `presets`, `preferences`, `trace-metadata`.
- `write_trace_asset`: raw byte request body (maximum 20 MB); atomically writes
  a uniquely named asset and returns its `assetId` string.
- `read_trace_asset({ assetId })`: returns a raw ArrayBuffer. Asset IDs are UUIDs
  generated by Rust, not filesystem paths.
- `prune_trace_assets({ keep })`: removes obsolete assets after a successful
  metadata write; `keep` is the current assetId or null.
- `confirm_action({ message })`: returns boolean using native OK/Cancel.
- `confirm_unsaved({ name })`: returns `save`, `discard`, or `cancel`, using a
  native Save/Discard/Cancel dialog.
- `confirm_conflict()`: returns boolean; true means Save As, false means Cancel.
- `set_document_title({ name, dirty })`: sets the main-window document title.

Use `@tauri-apps/api/core` invoke for commands. Binary requests use invoke's raw
payload and request headers; do not serialize image/export bytes as JSON arrays.
Native adapter uses `@tauri-apps/api/window` to listen for close requests and to
destroy the window only after successful document protection and storage flush.

## Persistence

Native state lives in the application data directory. JSON state records use
fixed filenames, serialized atomic writes, and no caller-supplied paths.
Tracing metadata contains `assetId`, `mime`, and the existing TraceImage fields
except `asset` and `url`. Stage the asset, atomically write the metadata, then
prune old assets. This preserves the previous valid guide when a write fails.

Browser storage keeps its existing localStorage keys and IndexedDB database.
Desktop hydration recovers documents as dirty, with no active project token.
Save then requires a chosen destination. Recovery can store plain version-1
project JSON. A controller keeps the last saved serialization in memory;
Discard writes that snapshot to recovery, or removes recovery for an untitled
document. Flush pending recovery/preset/preference/trace writes before closing.

## Document commands

Track active file token, display path, and last saved serialization outside the
document. Capture a save snapshot before awaiting disk I/O. Mark clean only if
the editor still matches that snapshot after a successful write. Exporting a
project copy does not retarget or mark the desktop document saved.

Open parses and validates its candidate before replacing the current document.
Cancellation, invalid input, failed saves, and cancelled protection leave the
document, selection, tracing guide, and undo history intact. New/Open/Close use
Save/Discard/Cancel on desktop; browser keeps its existing confirmations.

Native window close requests are prevented immediately, then handled through
the same document controller. Only destroy after protection and persistence
flush. If writes fail, keep the window open with actionable error feedback.
Application Quit requests also route through window close protection, including
the macOS application menu and Cmd+Q. Exit is allowed after the main window has
been destroyed by the controller.

## Test builds

The `desktop-e2e` Cargo feature is debug-only. It enables the embedded WDIO
driver, isolated test data, and these commands (absent in shipped builds):

- `test_reset`: clears isolated state, tokens and queued dialog responses.
- `test_fixture({ name, data })`: writes UTF-8 fixture data inside the isolated
  test-files folder and returns its path. Name must be a plain basename.
- `test_queue_file({ path })`: queues a picker result, with null for cancellation.
  Paths must stay in the test-files folder.
- `test_queue_choice({ choice })`: queues `save`, `discard`, `cancel`, `ok`, or
  `no` for native confirmation dialogs.
- `test_read_file({ name })`: reads an isolated UTF-8 output fixture.
- `test_read_bytes({ name })`: returns binary output from an isolated fixture.
- `test_corrupt_file({ name, data })`: changes a selected fixture externally.
- `test_request_close`: sends a native close request to test document protection.
- `test_request_quit`: sends an application exit request to test Quit protection.
- `test_pending_dialogs`: reads queued picker/confirmation counts so tests wait
  for the controller to handle a close or Quit request before asserting.

The test runtime uses `BRICKPRESS_TEST_DATA_DIR` only when `desktop-e2e` is
enabled, uses a separate webview data directory, and disables single-instance
and window-state persistence to avoid changing real user data.
